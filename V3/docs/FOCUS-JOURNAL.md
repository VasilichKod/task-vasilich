# Журнал фокуса

Журнал — представление задач выбранной недели, а не отдельный список и не
автоматический перенос. Он доступен через плавающую кнопку в графике.

- «К этому дню»: от начала выбранной недели до сегодняшнего дня включительно.
- «Вся неделя»: все дни выбранной недели, включая будущие.
- Учитываются добавленные в график проекты и их обычные и постоянные задачи.
- По умолчанию завершённое скрыто. Его можно показать переключателем.
- Порядок: сначала явно важные, затем текущий доход, затем плановые дни.
  Можно переключиться на порядок только по дням.

## Отметки

`focusArea` проекта — направление по умолчанию. `focusArea: null` у задачи
означает наследование от проекта; `unassigned` — явную отметку «Без отметки».
Направления: `income`, `growth`, `health`, `family`, `personal`, `life`,
`unassigned`. Отметка дохода вводится человеком и не является расчётом прибыли.

`important` — отдельная ручная отметка. Она не зависит от направления:
важные дела семьи и здоровья могут стоять выше обычных рабочих дел.
У постоянной задачи направление и важность относятся ко всем её повторам.

Отметки хранятся на сервере, входят в экспорт планирования и сохраняются
при переносе. Клиенты без новых полей не стирают сохранённые отметки.

## Баланс

Выполнение записывает `completedAt`; отмена выполнения очищает его.
Баланс считает задачи по фактической дате выполнения, включая дела из списка
задач и статусы постоянных задач. У исторических записей точная дата неизвестна:
для задач графика используется плановый день с явным пояснением в интерфейсе.
Завершённые дела из списка без даты исключены из периодов и показаны счётчиком.

Распределение по направлениям отражает число записанных выполненных дел,
не время, усилия, удовлетворённость или финансовый результат.
Отсутствие записей не означает отсутствия деятельности в жизни.

## Проверка

`scripts/check-focus.ts` проверяет сервисы планирования и bootstrap:
наследование, переопределения, фактические даты, повторную синхронизацию,
старые клиенты и конфликты версий.
Он запускается только с явно выделенной временной PostgreSQL-базой
`127.0.0.1:55439/nedplan_focus_test`, после `prisma migrate deploy`.
Никакие рабочие базы скрипт не принимает.
